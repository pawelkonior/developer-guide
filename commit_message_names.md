##  Commit Message Types (Conventional Commits)

| **Type**   | **Meaning** |
|-------------|-------------|
| `feat`      | New feature or functionality |
| `fix`       | Bug fix |
| `docs`      | Documentation only (no code changes) |
| `style`     | Code formatting or linting (no logic changes) |
| `refactor`  | Internal code restructuring without changing behavior |
| `perf`      | Performance improvements |
| `test`      | Adding or updating tests |
| `build`     | Build system or dependency updates |
| `ci`        | Continuous integration or deployment changes |
| `chore`     | Maintenance tasks, configuration, or cleanup |
| `revert`    | Revert a previous commit |


## Example:

```bash

<type>(<scope>): <short description>

feat(auth): add JWT-based authentication
fix(api): handle missing headers
docs(readme): update setup instructions

```
